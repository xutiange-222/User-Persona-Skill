# 交付质量契约

本文件定义所有 R1 至 R5、toB、toC、toD 共同遵守的质量标准。开始执行前读取本文件；任何一项失败都回到最早受影响的检查点。

| 质量维度 | 合格标准 | 机器门禁 |
|---|---|---|
| 输入完整性 | 每份纳入资料有唯一内容哈希；重复、补充材料、排除材料和分配关系可解释 | `validate_source_manifest.py` |
| 范式正确性 | R1-R5 的选择、分类结构、画像成员和 R4/R5 总览前后一致 | `validate_paradigm_contract.py` |
| 事实准确性 | 事实不推断；每条引文能回到原材料；来源、画像归属和证据层级正确 | `validate_evidence_traceability.py`、`validate_evidence_contract.py` |
| 内容完备度 | 03 选中的每个字段都完成逐份抽取、逐画像归并并进入 04；未展示字段有用户确认的省略理由 | `validate_content_completeness.py` |
| 研究表达 | 共性、少数观点、分歧和材料未提及分开；标题语义完整；正文清晰、具体、简洁；技术 token 可回到材料或用户上下文 | 固定 prompt、`check_personas_json.py`、`validate_language_quality.py` |
| 旅程可信度 | 阶段综合显式标记；行为、节点、工具、痛点、触点和情绪逐项有证据 | `validate_journey_checkpoint.py` |
| 过程可迁移 | MD 可独立审阅和复制；JSON 含研究上下文快照、确认状态和完整真值 | `validate_checkpoint_pairing.py` |
| 视觉正确性 | 仅使用注册组件和设计 token；无截断、遮挡、错色、字号或几何错误 | component schema、`validate_html.py` |
| 恢复可靠性 | 上游修改使所有下游失效；恢复脚本只返回一个最早可执行步骤 | `recovery_check.py` |

## 内容判断顺序

对每个字段和旅程元素按以下顺序判断：

1. 找到材料中的直接事实和逐字证据。
2. 材料没有提到时写“材料未提及”。
3. 多位受访者意见不同时分别保留共性、分歧和少数观点。
4. 研究者综合使用 `synthesis`，用户补充使用 `user_context`。
5. 只保留与 00 研究问题和决策用途相关的结论。
6. 标题优先保证语义完整，再压缩到一行可读。条目小标题通常 4–16 字，画像名可到 24 字。禁止为了满足长度截断产品名、技术术语或动作对象，禁止在标题末尾写 `…`、`……` 或 `...` 代替缺失内容。
6. 用完整、具体、可独立理解的一句话表达，随后再压缩冗余词。

## 完备度定义

- 文件完备：输入、processed、extracted 一一对应。
- 字段完备：03 选中的字段在每份适用抽取和每个画像归并中存在；缺失也要显式记录。
- 证据完备：每个事实结论至少有一条直接证据，证据来源属于当前画像。
- 画像完备：04 包含全部选定字段、差异、风险和最终展示组件。
- 旅程完备：所有用户要求的画像都存在旅程，或整份 04 旅程明确不适用。
- 报告完备：所有选定字段都通过 04 组件进入 05；省略项逐条说明信息损失并由用户确认。

## 五范式共同失效规则

- 研究目标变化：00 及全部下游失效。
- 范式或分组变化：01/02 及全部下游失效。
- 字段变化：03、extracted、reduced、04、05 和 HTML 失效。
- 画像名称或成员变化：04-personas、04-journeys、05 和 HTML 失效；若改变分类真值，回到 01/02。
- 旅程变化：04-journeys、05 和 HTML 失效。
- 页面或视觉选择变化：05 和 HTML 失效。

禁止只修改后续文件来掩盖上游真值变化。
