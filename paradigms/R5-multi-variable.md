# R5 多维分布

## 使用条件

研究需要 3 到 5 个区分点共同解释用户差异，二维矩阵承载不足。toB、toD、toC 均可使用。

## 02 是本范式核心

使用 `assets/prompts/recommend-value-variables.md` 推荐 3 到 5 个区分点。每个区分点必须满足覆盖性、差异性和决策相关性。

若只有两个区分点有充分证据，建议用户切换 R4。超过五个时先精简，避免分布图和用户确认负担失控。

## 固定确认顺序

在 `02-classification.md` 中分四轮确认：

1. 确认区分点及定义。
2. 确认每个区分点的 2 到 3 个档位名称和行为边界。
3. 确认每位匿名受访者的档位映射和原话证据。
4. 确认聚类、画像名称、成员归属和每类的档位特征。

用户确认全部名称和映射后写 `02-classification.json`，必须包含：

档位名确认闸门：这些词会进入最终报告。只有用户确认全部档位名后，才允许写入 `label_confirmed: true`。

```json
{
  "checkpoint": "02-classification",
  "status": "confirmed",
  "label_confirmed": true,
  "value_variables": [],
  "respondent_mapping": {},
  "groups": [],
  "empty_groups": [],
  "confirmation_message_summary": "用户确认区分点、档位名、映射和聚类结果。"
}
```

## 聚类要求

- 聚类依据是已确认的档位组合。
- 同类用户允许存在少量差异，差异必须在 02 和 04 中保留。
- 单人类别可以保留，同时记录样本量风险。
- 聚类超过五类时让用户决定合并或调整区分点。
- 所有人落点过于接近时回到区分点选择。

## 命名要求

- 类型名简洁直观，复杂差异写入副标题和画像描述。
- 档位名使用可观察的行为表达。
- 分布图、画像页和旅程页使用同一组类型名。

## 后续执行

1. 完成 03 字段、素材、旅程范围和视觉选择。
2. 按确认后的类别独立抽取和 reduce。
3. 在 04 确认画像内容和证据风险。
4. 在 04 旅程检查点确认每类旅程。
5. 05 使用 `layout-distribution-multi` 总览，子页按 research type 选择组件族。

## 质量门禁

- 05 的档位、曲线、颜色和画像成员必须与 02 一致。
- 每个画像只使用自己的 2C 色卡，分布图曲线颜色与画像色卡一致。
- 旅程内容逐项复用 `04-journeys.json`。
